# Cierre del pulido del importador automático

Base: main `ac41a0063680977dc2add1ad3d06daa0d4fac33e`, sincronizada con origin/main al iniciar. Fecha: 7/10/2026. Cambios locales; sin commit ni push.

1. **Archivos modificados.** Dominio: `catalog-detection.ts`. API: `supplier-catalog.service.ts` (orden) y `catalog.service.ts` (ocultar campo interno). DB: schema Prisma y nueva migración `20261007220000_catalog_prefix_order`. UI: `supplier-catalog.tsx`, componente puro `catalog-import-preview-table.tsx` y estilos específicos en globals.css. Pruebas: nueva `catalog-heading-normalization.test.ts`, ampliación de supplier-catalog.integration/catalog-migration.integration, nuevo test de preview web y configuración del runner nativo en web/root. Se actualiza arquitectura vigente y este reporte. No se modifica el dominio Product/Identification/Inventory, matching, import/commit, contratos, extractor, seguridad ni migraciones previas.

2. **Normalización/detección.** Se conservan aliases exactos y fingerprint v3. Para encabezados largos se normalizan tildes, mayúsculas, puntuación y espacios; se eliminan DE/DEL/LA/EL/Y y se traducen abreviaturas comunes. Una gramática de palabras completas permite solo conceptos y calificadores comerciales conocidos. No se aplica similitud ni inferencia por substring. Ejemplo: «Cód. del artículo» → codigo/producto → supplierCode; «Nombre del proveedor» no se transforma en descripción de artículo.

3. **Equivalencias.** COD/CODE → código; ART/ARTICULO/PRODUCT → producto; REF → referencia; NRO/NUM → número. Descripción/detalle/nombre con producto; precio/valor/importe con unitario/lista/neto; alícuota/tasa/porcentaje con IVA; unidad/medida; marca/modelo/categoría/presentación del producto; fabricante/laboratorio; EAN/UPC/GTIN y código de barras. Se mantienen las equivalencias previas en español/inglés. Una palabra o calificador desconocido impide reconocer el encabezado extendido.

4. **Ambigüedades.** Dos columnas plausibles conservan REVIEW y mapping null, incluso «Marca del producto / Marca producto 2» o «Precio de lista / Precio unitario». Si falta evidencia esencial, la hoja no se selecciona automáticamente. Opcionales dudosos quedan sin informar. Las heurísticas de contenido continúan requiriendo revisión y no habilitan importación automática por sí solas.

5. **Preview.** Ocho columnas: fila, código MaxBio, código proveedor, descripción, marca, precio, IVA y resultado. Detalles nativos por fila conservan alternativo, fabricante, modelo, categoría, presentación, unidad, GTIN original/normalizado, moneda e incluye IVA. Errores/conflictos/advertencias siempre visibles; errores y conflictos abren sus detalles. «Nueva referencia» hasta commit, código definitivo cuando existe, ausencia «—». El mismo componente sirve para previa e historial confirmado. Se conserva formato exacto de precio y moneda explícita en el precio.

6. **Orden Z → AA.** Orden global server-side por longitud del prefijo, prefijo y secuencia: A…Z, AA, AB. DESC invierte los tres criterios. ID garantiza desempate; los demás sorts también desempatan por identidad lógica. Búsquedas/filtros/paginación permanecen en Prisma/PostgreSQL, sin descargar referencias para ordenarlas. El orden local del proveedor conserva referenceSequence.

7. **Migración.** Nuevo entero nullable privado `Supplier.catalogPrefixLength`, calculado siempre por trigger y validado con CHECK; índice tenant/longitud/prefijo. La migración hace backfill sin tocar prefijos, códigos, secuencias, versiones ni historia. Se evaluó una expresión SQL no persistida: orderBy de Prisma no la representa; se eligió este dato mínimo por proveedor para evitar un segundo motor de filtros o paginar en JavaScript. Las doce migraciones aplican mediante Prisma Migrate, nunca db push.

8. **Tests agregados.** Cinco unitarias de encabezados con matrices de variantes/reordenamiento, fila 1/16, opcionales ausentes y negativos. Tres pruebas de HTML generado por React para ocho columnas, datos secundarios, detalles abiertos en errores, mensajes fuera de detalles, códigos existentes/nuevos y monedas. Integración nueva: 28 proveedores, dos referencias por proveedor, ambos sentidos y ocho páginas de siete filas; cubre Z/AA/AB, sorts secundarios, filtro local, trigger que corrige manipulación del campo, búsqueda y cero productos/identificadores/vínculos/stock. Backfill V2 existente comprueba el dato derivado y conservación de asociaciones.

9. **Comandos ejecutados.** Pasaron `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm format`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, `pnpm test:database` y `pnpm build`. Prisma `migrate deploy`, `migrate status` y `migrate diff --from-config-datasource --to-schema prisma/schema.prisma --exit-code --script`. La instalación no alteró pnpm-lock.yaml; no se agregan dependencias.

10. **Resultados.** Unitarias API 59/59; preview web 3/3; integración API 99/99; integración de base 1/1: 162 pruebas, cero fallas, cero skips con el Excel habilitado. La nueva prueba ordinal atravesó Z/AA/AB en ambos sentidos y ocho páginas, además de desempates de precio/descripción/proveedor; duró 3,10 s. Migración aplicada; status informa doce migraciones al día; diff vacío, exit 0. From-zero de Inventory y transición desde V2 se verifican en bases efímeras mediante Prisma Migrate. La aceptación del Excel original pasó: 2.924 referencias, encabezado 16, precio 218505.12 y cero errores/conflictos, sin confirmar comercialmente el archivo. Se conservan las suites de Inventory/Identification y la invariante de cero nuevos productos/identificadores/vínculos/movimientos/balances al importar. El Excel no se agrega a Git.

11. **No ejecutado.** Browser/E2E visual de desktop/móvil: CUA devolvió apps=[] y browsers=[]. Las pruebas de React verifican HTML estático, no apariencia, interacción real ni viewport. No se afirma verificación visual.

12. **Riesgos/pendientes.** Aplicar la nueva migración antes de ejecutar la API en otro entorno; usar Prisma Migrate. No hay cambios de códigos ni reutilización de prefijos. Vocabulario deliberadamente acotado: extensiones futuras deben traer fixtures y casos negativos. El endpoint ADMIN `catalog-imports/analyze` con sheet/headerRow queda como diagnóstico de solo lectura; no aparece en la UX ni sustituye preview/commit. Pendiente revisar visualmente la preview en desktop/móvil con navegador disponible.

Flujo verificado: archivo → inspect → preview automático → staging/filas → render de tabla compacta → commit. El reporte distingue integración HTTP, persistencia y render HTML de la navegación visual no disponible.
